# 프로젝트 룰

`crispin-review-bot` 은 crispin-lab 조직 PR 을 리뷰하는 봇이다. 로컬 스킬(`skill/`)과 GitHub Action
(`action.yml`)이 **같은 CLI(`bin/pcr`) · 같은 프롬프트(`prompts/`) · 같은 스키마(`schemas/`)** 를 쓴다.
한쪽에만 절차를 추가하지 않는다 — 두 실행 경로가 갈리면 같은 PR 에 다른 리뷰가 달린다.

## 책임 분리

- **절차는 코드(`pcr/`)**: GitHub 호출, 지문 계산, 중복 제거, 라인 검증, 반응, 재시도 판단.
- **판단은 프롬프트**: 무엇이 문제인가, 답글 의도가 무엇인가. 판단 단계는 읽기 전용 도구만 갖고
  JSON 만 반환한다. GitHub 에 쓰는 권한을 판단 단계에 주지 않는다.
- 외부 의존성 없이 Python 표준 라이브러리만 쓴다 (로컬 · 러너 어디서나 바로 돈다).

## 생성 도구 표기 금지 (절대)

- 봇이 게시하는 모든 본문(리뷰 요약 · 인라인 · 답글 · 안내 코멘트)에 생성 도구 표기, 서명, footer,
  `Co-Authored-By`, "자동 생성" 류 문구를 넣지 않는다. `pcr/sanitize.py` 가 게시 직전에 지우고,
  남아 있으면 게시를 거부한다. 이 검사를 우회하는 게시 경로를 만들지 않는다.
- 이 레포의 커밋 메시지 · PR 본문 · 코드 주석 · 문서에도 같은 규칙을 적용한다.
  `Co-Authored-By:`, `Generated with/by …`, 세션 링크처럼 **무엇이 이 내용을 만들었는지** 밝히는 표기를
  쓰지 않는다. 이 도구가 무엇을 쓰는지(`claude` CLI 등) 설명하는 문서 내용은 해당하지 않는다.

## 커밋

- Subject: `[CIT-N]: 한국어 제목` (70자 이내). 티켓이 어색한 툴링 변경은 `[chore]: 한국어 제목`.
- 본문은 한국어 불릿, *왜* 를 설명한다.
- 파일은 이름으로 명시 스테이징한다 (`git add -A` 금지).

## 문서

- `.claude/` · `skill/` · `README.md` 는 한국어. 기술 용어 · 명령어 · 경로 · 식별자는 원어 그대로.
